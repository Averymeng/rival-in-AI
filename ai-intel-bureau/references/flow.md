# 流程详解与示例

本文档是 SKILL.md 第 3 节的展开：完整流程、计划卡结构、报告示例。

## 一、流程三步（只确认 1 次）

### 步骤 1 · 解析
LLM 从用户输入抽出四要素：
- **分析对象**（1-3 个，从输入解析）
- **意图**：对标差距 / 差异化机会（找机会·规划产品·选型）/ 选型 / 纯研究
- **维度**：默认全选 7 维，或按提问侧重
- **深度**：快 / 标准 / 深（默认标准）

模式判定：
- 用户点名 2-3 个 → **对比模式**（只比这几个）
- 用户只给 1 个 → **竞品分析模式**（深析主体 + 对比 5 个竞品）

对象不明或明显非 AI → 追问**一个问题**（A/B/C/D 选项），不连环追问。

### 步骤 2 · 一次轻确认（分析计划卡）
仅展示一次，用户确认或编辑后进入查证。

### 步骤 3 · 生成
查证（多源）→ 写报告（6 模块 + 约定写法）→ 渲染（build_report.py）。

## 二、分析计划卡 · 结构
- 分析对象（从输入解析出的 N 个）
- 对比对象（对比模式=点名的几个；竞品分析模式=预置清单初稿的 5 个，确认后实搜修正）
- 分析意图
- 选用维度（勾选的几个方面）
- 深度（快 / 标准 / 深）
- 输出形式（可视化报告）
- 操作：〔确认〕〔编辑〕

### 计划卡示例（对比模式）
```
【分析计划卡】
· 分析对象：Kimi（月之暗面）、豆包（字节）
· 对比对象：Kimi、豆包（仅此两个，正面对比）
· 分析意图：对标差距
· 选用维度：市场与定位 / 核心功能与AI能力 / 用户体验 / 商业模式与定价 / 增长与运营
· 深度：标准
· 输出：可视化报告
        〔确认〕        〔编辑〕
```

## 三、报告示例（对比模式：Kimi vs 豆包）

```markdown
## 一句话结论
- 豆包凭字节流量与免费策略在 C 端渗透更快；Kimi 以长文本+学术合规在垂直专业用户中更强；二者都尚未深耕"多模态 Agent 工作流"这一空白。

## 核心发现
- 豆包：免费 + 抖音导流，C 端 MAU 领先（来源：公开报道，未查证具体数）
- Kimi：长文本（200 万字）为差异化标签（来源：官网）
- 共同短板：端侧/隐私对话、企业知识库深度集成

| 产品 | X轴(通用↔专业) | Y轴(流量生态↔模型能力) | 规模(声量) |

| 豆包 | 8 | 5 | 9 |
```
