## 1. 总体原则
1. **轻量先跑通**：优先用已验证的"技能 + 工作流"原型验证核心价值，再考虑工程化，避免在数据库 / 向量库上过早投入。
2. **不被原产品需求文档技术栈绑架**：持久化知识库、检索增强生成、流程编排框架、量化评测全部后置。
3. **渐进交付**：每个阶段都有可验证产物，先有"能用的闭环"，再有"好用的产品"。
4. **复用原型资产**：直接继承 AI 情报局已验证的"研究简报 + 约定写法渲染 + 证据纪律"。

## 2. 技术选型（最小可行产品简化 vs 原产品需求文档全栈）

| 模块 | 原产品需求文档全栈 | 最小可行产品落地 | 说明 |
|---|---|---|---|
| 前端 | Next.js | 先做自包含可视化 HTML 模板，后续上 Next.js | 第一版零依赖，便于快速验证 |
| 后端 | FastAPI | 先由技能 / 轻量脚本承载，后续引入 FastAPI | 先验证逻辑，再补服务化 |
| 数据库 | PostgreSQL + pgvector | 暂不做 | 实时检索即可，无持久化 |
| 检索增强生成 | 向量数据库 | 实时检索 | v1.1 起评估 |
| 流程编排 | 流程编排框架（LangGraph） | 顺序工作流（提示词编排） | 固定流程无需复杂编排 |
| 评测 | 多指标体系 | 后置 | 上线后迭代 |

## 3. 分阶段实施计划

### 阶段 0：设计定稿（已完成）
- 维度 10 维定稿（见《操作日志》第三节）
- 研究目标类型 5 类
- 证据纪律规则
- 可视化图表类型与报告 11 章节
- 产出：《产品需求文档》《产品搭建流程》《操作日志》

### 阶段 1：技能 / 工作流原型（WorkBuddy 内跑通）
- 编写本项目技能，继承 AI 情报局：研究简报、约定写法 → 可视化渲染、证据纪律
- 在对话中实跑 5 类研究目标样例（产品分析 / 竞品对比 / 市场扫描 / 产品选型 / 机会探索）
- 产出：可运行的技能 + 样例报告 + 渲染脚本

### 阶段 2：网站产品化
- **后端**：轻量服务封装"解析 → 研究简报 → 检索 → 分析 → 报告"逻辑（调用大模型 + 实时检索）
- **前端**：输入框 / 对话式提交 → 展示可视化报告页
- **复用**：阶段 1 的渲染层直接复用
- **部署**：前端 + 后端挂到可公网访问处，实现"输入查询 → 生成可视化页面"

### 阶段 3：上线 + 可选增强
- 正式上线发布
- 可选增强（按需求优先级）：
  - GitHub / Hacker News / Reddit 深度接入
  - 定时刷新（先做"定时重跑固定查询"的工作流版，非自主智能体）
  - 交互式可视化升级（ECharts 等）
  - 扩展到 AI 之外的领域（配置化维度与预置清单）

## 4. 各模块落地指引

### 4.1 意图解析与澄清
- 意图分类：5 类研究目标 + 双模式判定
- 选项式追问：每次一个问题，优先给 A/B/C/D 选项
- 解析产出：对象（1–3 个）、目标类型、限定维度、模式

### 4.2 研究简报
- 结构化模板：对象 / 对比对象 / 意图 / 维度 / 深度 / 输出
- 一次确认机制，确认后进入研究

### 4.3 实时检索
- 并行检索策略：按维度分批查询
- 来源优先级：官方网站 > 帮助文档 / 定价页 > 产品博客 / 版本发布说明 > GitHub / 社区（Reddit / Product Hunt）> 行业新闻
- 交叉验证：关键事实至少两源印证

### 4.4 证据系统
- 结论-来源绑定规范（结论 / 来源 / 时间 / 类型 / 可信度）
- 事实 / 洞察 / 建议 三类标注
- 未查证标注，严禁编造

### 4.5 分析引擎
- 10 维度评分口径（5=领先，3=平均，1=基本不覆盖，按需调整）
- 维度固定不可擅自增减；加深深度 = 同维度更深，不补维度

### 4.6 可视化渲染（约定写法规范）
| 约定写法 | 渲染图表 |
|---|---|
| 1–5 分矩阵（维度 × 对象） | 能力雷达图 + 维度热力矩阵 |
| 步骤 → 步骤 → 步骤 | 关键任务路径流程图 |
| 必须 / 应当 / 可以 | 优先级看板 |
| 摘要结论条目 | 摘要卡片 |
| 含来源 / 链接的表格 | 证据卡片 |
| 定位坐标（X / Y） | 市场地图（定位散点） |

## 5. 验证与评测（后置说明）
v1.1 起建立量化评测体系：
- **检索评测**：前 K 项召回率
- **生成评测**：忠实度、引用准确度、完整度、洞察质量
- **产品评测**：任务完成率、出报告时长、用户满意度

## 6. 风险与回滚
| 风险 | 应对 |
|---|---|
| 实时检索质量不达标 | 增加来源类型 + 强制交叉验证 |
| 渲染样式不佳 | 升级前端（后续引入图表库） |
| 网站上线稳定性 | 后端限流 / 结果缓存 / 失败重试 |
| 范围蔓延 | 严格按《产品需求文档》第 6 节边界，后置项单列管理 |
