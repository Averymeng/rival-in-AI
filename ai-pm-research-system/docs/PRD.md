# AIPM·瞭望台 · 产品需求文档（PRD）

> 版本：v1.0（评审中）｜ 整理时间：2026-08-25
> 适用对象：产品决策者、开发、面试评审
> 关联文档：`内容架构.md`（报告内容设计）、`AGENT_HANDOFF.md`（如何让 agent 复刻本产品）

---

## 1. 一句话定位

**面向 AI 产品决策者（AI PM / 创业者 / 研究员 / 投资人）的智能研究与报告生成系统**：用户用自然语言输入一个研究目标（产品分析 / 竞品对比 / 市场扫描 / 产品选型 / 机会探索），系统实时联网检索公开信息、按固定分析框架撰写，并产出**结构化、带证据来源、可视化**的研究报告。

领域限定：仅 AI 相关（大模型 / 对话 / 绘画视频 / 办公效率 / 营销 / 编程 / 搜索 / 公司·基建等）。

---

## 2. 目标用户与核心价值

| 用户 | 典型场景 | 本产品替他解决 |
|---|---|---|
| AI 产品经理（0–5 年） | 立项前竞品调研、版本复盘、选型 | 把数小时跨源调研压缩为一次提交 |
| AI 创业者 | 找赛道空白、验证差异化 | 快速看清竞争格局与机会点 |
| 行业研究员 | 输出可复用分析 | 统一框架 + 可溯源，便于沉淀 |
| 关注 AI 赛道的投资人 | 扫赛道、看公司 | 实时、按需、低成本，替代高价静态报告 |

**三大核心价值**
1. **效率**：把"数小时跨源调研"压缩为"一次提交 + 一份报告"。
2. **可信**：证据可追溯（结论-来源绑定），从机制上抑制幻觉。
3. **可复用**：结构化可视化，可直接用于评审 / 立项 / 竞品跟踪。

---

## 3. 背景与痛点

AI 行业迭代极快，信息高度分散于官网 / 博客 / 社区 / 新闻 / 代码仓库。人工调研痛点：

- **信息分散耗时**：要跨多个站点拼信息。
- **来源不可信**：结论无出处，容易以讹传讹。
- **缺乏统一框架**：每次分析角度不一样，难比较。
- **产出非结构化**：笔记散落，难沉淀、难汇报。

---

## 4. 产品入口：5 类研究目标

| # | 研究目标 | 输入示例 | 输出重点 |
|---|---|---|---|
| 1 | 产品分析 | "系统分析一下可灵" | 单主体深析 + 默认竞品对比 + 机会点 |
| 2 | 竞品对比 | "Kimi 和 豆包长文本谁强" | 仅比点名对象，限定维度高亮 |
| 3 | 市场扫描 | "AI 视频生成有哪些玩家" | 盘点一条赛道 |
| 4 | 产品选型 | "小团队选哪个 coding agent" | 按需求给选型建议 |
| 5 | 机会探索 | "AI PPT 还有哪些空白" | 找未覆盖方向 |

支持自然语言（"分析一下可灵"）与结构化（直接填 1–3 个对象名）输入。

---

## 5. 双模式（核心交互逻辑）

| 模式 | 触发 | 行为 |
|---|---|---|
| **对比模式** | 用户点名 N 个对象（N≥2） | 仅就这 N 个正面对比，不引入外部竞品 |
| **竞品分析模式** | 用户仅给 1 个主体（"系统分析可灵"） | 先深析主体，再对比预置默认 5 个竞品，含机会点模块 |
| **单品模式** | 仅指名 1 个且无对比意图 | 只深析该单品 |

**零确认直跑纪律**：解析完成后默认直接检索出报告，不弹确认卡。唯一例外：仅当「单对象且措辞无法判定产品分析 / 竞品分析」时，弹一个 A/B 轻询问。其余字段用默认值；报告顶部以一行「**本次假设**」明示本次口径，确认动作后置到看报告后（用户可增量重跑，如"加 Trae""只盯定价"）。

---

## 6. 功能需求

1. **意图解析与澄清**：产出 对象 / 类型 / 限定维度 / 模式；信息不足时选项式补全（每次只问一个、优先给选项）。
2. **实时检索**：每次研究实时联网检索，来源含官网 / 帮助文档 / 定价页 / 博客 / 发布说明 / GitHub / Reddit / Product Hunt / Hacker News / 行业新闻。不做持久化知识库、不做 RAG（v1.1 起评估）。
3. **证据系统**：每条重要结论绑定 结论 / 来源 / 时间 / 来源类型 / 可信度，分 事实 / 洞察 / 建议 三类；缺失标"未查证"，严禁编造。
4. **分析引擎**：固定 10 维度（详见 `内容架构.md` §2）。
5. **可视化报告**：11–12 章节 + 约定写法 → ECharts 图表（雷达 / 散点地图 / 时间线 / SWOT / 优先级看板等）。
6. **报告交付**：输出可视化网页 + 来源清单，支持历史列表、归档与分享。

---

## 7. 非功能需求

- **性能**：标准深度下报告生成中位时长 30–90 秒（随实测迭代）。
- **可靠性**：来源缺失标"未查证"，绝不编造数据 / 份额 / 融资。
- **安全合规**：仅用公开信息，不抓取需登录授权的内容。
- **可扩展**：维度、预置清单、图表类型做成可配置，便于扩展到 AI 之外。

---

## 8. 产品边界（明确不做）

MVP 聚焦**单次研究闭环**（输入 → 解析 →〔仅模式歧义时轻询问〕→ 检索 → 分析 → 可视化报告）。

后置 / 明确不做：
- 持久化产品知识库、检索增强生成（RAG）
- 流程编排框架（LangGraph 等多智能体）
- 量化评测体系、持续追踪 / 订阅 / 历史积累
- 多智能体并行调研

> 取舍哲学：MVP 聚焦单条可验证闭环，避免为"显得高级"引入复杂度；自包含渲染器已成熟，网站化只丢胶水代码；诚实优先（原型就是原型，不把"待验证"写成"已实现"）。

---

## 9. 竞争与差异化

| 对比对象 | 差异点 |
|---|---|
| 通用搜索引擎 | 统一分析框架 + 证据纪律，而非零散链接 |
| 通用 AI 助手 | 决策导向、结构化、可视化、可复用，而非一次性问答 |
| 付费行业报告 | 实时、按需、低成本，而非高价静态报告 |

---

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 实时检索质量依赖模型与搜索能力 | 多源并行 + 交叉验证 + 来源优先级 |
| 信息时效性 | 报告标注数据时间，关键结论标来源时间 |
| 幻觉风险 | 证据纪律（结论-来源绑定、事实/洞察/建议分类、未查证标注） |

---

## 11. 对外表达边界（简历 / 面试 / 汇报）

- **状态**：写"原型 / 离线验证"，不写"上线系统"。
- **用户**：写"面向…设计 / 用公开样本验证"，不写"服务了 N 位用户"（无真实用户记录）。
- **指标**：不写提升百分比；量化评测体系未建，相关能力标"待验证"。
- **技术词**：每个词都能答"解决哪个节点、为何不用更简单方法、怎么失败"——答不出就删。

---

## 12. 关键指标（北极星 / 过程指标）

- **北极星**：单次研究从提交到可信报告的中位时长（目标 ≤ 90s）。
- **过程指标**：来源命中率（结论带有效来源占比）、架构师复核通过率、增量重跑使用率。

> 注：以上为设计目标，当前为原型验证阶段，未做规模化埋点统计。
