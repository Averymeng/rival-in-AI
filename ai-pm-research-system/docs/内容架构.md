# AIPM·瞭望台 · 报告内容架构

> 本文档定义**报告本身的内容设计**：一份报告由哪些板块组成、各板块的业务语义、支撑的分析维度、证据规则，以及它如何对应 AIPM 的真实工作流。
> 关联：`PRD.md`（产品需求）、`AGENT_HANDOFF.md`（如何让 agent 生成这份报告）。

---

## 1. 设计原则

报告不是"一份分析报告"，而是把 AI PM 从「立项 → 跟踪 → 规划 → 选型 → 汇报」的完整工作流一次性串起来。内容设计遵循三条原则：

1. **按业务语义分层**：决策层 → 认知层 → 对标层 → 行动层 → 可信层，从结论到证据，由薄到厚。
2. **证据可追溯**：每条重要结论绑定来源，从机制上抑制幻觉。
3. **约定写法 → 可视化**：内容用固定 Markdown 约定撰写，由渲染器映射成图表（写作者只管内容，改视觉只动渲染器）。

---

## 2. 分析框架：固定 10 维度

排序固定（用户体验位于商业模式与增长之间；风险与短板永远置末）。维度无重叠，各为不同切面。

| # | 维度 | 看什么 |
|---|---|---|
| 1 | 市场与定位 | 目标用户、使用场景、品牌调性、赛道规模与位置 |
| 2 | 产品与核心功能 | 功能清单、核心场景覆盖、差异化功能点 |
| 3 | AI 能力 | 底层模型、基准表现、生成质量、上下文长度、一致性、生成速度 |
| 4 | 数据壁垒 | 数据资产（训练 / 反馈数据）、数据飞轮、护城河、隐私与合规 |
| 5 | 技术与生态 | 技术架构、API 开放、第三方集成、开源与开发者生态 |
| 6 | 商业模式与定价 | 免费 / 订阅 / 按量 / 企业版、价格带、变现边界 |
| 7 | 用户体验 | 易用性、界面、延迟、稳定性、客服（位于 6 与 8 之间） |
| 8 | 增长与运营 | 获客渠道、内容打法、社区、口碑、病毒机制 |
| 9 | 机会点 | 竞品未覆盖的空白、用户真实需求、可切入方向（按意图可选） |
| 10 | 风险与短板 | 合规风险、技术依赖、模式缺陷、竞争短板（置末） |

**评分口径**（在图表图例中轻量呈现，不单独成段）：1–5 分制，5 = 领先，3 = 行业平均，1 = 基本不覆盖。AI 能力按官方基准 + 实测；其余按公开资料 + 用户反馈综合判断（属分析洞察，非厂商披露）。

## 3. 证据系统：结论三类

| 类型 | 定义 | 示例 |
|---|---|---|
| 事实 | 可核实的客观信息 | "可灵由快手于 2024 年 6 月发布" |
| 洞察 | 基于事实的分析判断 | "其运动镜头稳定性构成差异化壁垒" |
| 建议 | 面向决策的行动建议 | "应在企业版补齐 API 配额" |

- 每条重要结论后附来源角标，报告末以来源卡片汇总。
- 无法核实或来源缺失 → 内部标注「未查证」；严禁编造功能 / 价格 / 数据 / 份额 / 融资。

## 4. 报告内容架构（12 板块，按工作逻辑分 5 层）

| 层 | 板块 | 业务语义 | 对应 AIPM 工作场景 | 可视化形式 |
|---|---|---|---|---|
| **决策层** | 执行摘要 | 核心判断 + 3–6 条关键结论 | 决策 / 汇报（一页看懂） | 核心判断卡 + 编号发现卡 |
| **认知层** | 市场概览 | 赛道规模、梯队、趋势 | 市场判断、立项背景 | 导语 + 竞争梯队金字塔 |
| 认知层 | 产品定位 | 各对象定位 / 调性 / 场景对照 | 看清"它到底是什么" | 产品档案卡 |
| 认知层 | 竞争格局 | 谁和谁竞争、强弱关系 | 竞品地图、战略定位 | 中心-竞品辐射关系图（SVG） |
| **对标层** | 功能矩阵 | 功能覆盖度对照 | 功能规划查漏补缺 | 能力覆盖矩阵 + 覆盖率 |
| 对标层 | AI 能力 | 模型 / 质量 / 速度等 | 技术选型依据 | 能力模块卡（含评分矩阵 → 雷达） |
| 对标层 | 商业模式 | 收费结构 / 价格带 | 商业模式借鉴 | 会员体系卡 + 变现结构对照 |
| 对标层 | 增长 | 获客 / 社区 / 口碑 | 增长打法参考 | KPI 指标卡 |
| **行动层** | SWOT | 自身优劣 + 机会威胁 | 战略研讨 | 2×2 象限矩阵 |
| 行动层 | 机会点 | 未覆盖空白 / 可切入方向 | 找差异化、立项切入点 | 面积气泡图（空白区） |
| 行动层 | 行动建议 | 落地优先级 | 路线图规划 | Must / Should / Could 看板 |
| **可信层** | 来源 | 所有引用的出处 | 复核 / 追责 / 复用 | 编号参考文献卡片 |

> 此外，报告内按需嵌入辅助图表：能力雷达（多维叠加）、市场 / 机会地图（散点气泡）、时间线（编年轨）、用户口碑（好评率 + 引述卡），分别服务于「对标层」「认知层 / 行动层」「认知层」「可信层」。

## 6. 约定写法（决定图表能否正确生成）

报告用固定 Markdown 约定撰写，渲染器据此映射图表。关键约定：

1. 第一行 `# 标题`（含研究对象名）。
2. 紧接 `## 本次假设`：键：值 列出 分析对象 / 研究意图 / 选用维度 / 研究深度。
3. `## 执行摘要`：`-` 列表 4–6 条关键结论。
4. 后续章节固定顺序：市场概览 / 产品定位 / 功能矩阵 / AI 能力 / 商业模式 / 增长 / 竞争格局 / SWOT / 〔机会〕/ 来源（机会按意图可选）。
5. `## 能力雷达` 下评分矩阵表：首列 `维度`，后续列为对比对象 + 必须保留 `行业平均` 基准列；单元格只填 1–5 数字。
6. `## 市场地图` 下表格：表头含 `X` `Y` `规模`，每行一个对象，X/Y 为 0–10 数值（定位散点）。含"机会"标题时渲染为机会地图。
7. `## 时间线`：`- 年份或日期：事件`。
8. `## 用户口碑`：`- 正面：…` / `- 负面：…`。
9. `## 来源`：表格 `来源｜链接`，不编造 URL，无来源写"未查证"。
10. 行动建议可用 `Must：` / `Should：` / `Could：`。

> 该约定是"内容"与"渲染"之间的契约。写作者只遵守写法，改视觉效果只动渲染器 `scripts/build_report.py`，二者解耦。

## 7. 单产品 vs 多产品变体

| 变体 | 触发 | 内容特点 |
|---|---|---|
| 多产品对比 | 用户点名 ≥2 对象 | 全表驱动（功能矩阵、评分矩阵、市场地图用表格多列） |
| 单产品（如可灵） | 仅 1 对象 | 功能矩阵用 是/否/强/中 标记；SWOT/增长为要点；行动建议内联 Must/Should/Could；仍含雷达（主体 vs 行业平均） |

渲染器需同时兼容两种变体，按表格结构自动判别，不依赖文件名。
