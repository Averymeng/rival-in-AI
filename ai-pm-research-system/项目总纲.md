## 0. 一句话定位

**面向 AI 产品决策者的智能研究与报告生成系统**：输入一个研究目标（产品分析 / 竞品对比 / 市场扫描 / 产品选型 / 机会探索），产出结构化、带证据来源的可视化研究报告。

领域限定：仅 AI 相关（大模型 / 对话 / 绘画视频 / 办公效率 / 营销 / 编程 / 搜索 / 公司·基建等）。

## 2. 设计理念（三大核心纪律 + 取舍哲学）

本项目不是"又一个 AI 问答"，而是一套**有纪律的研究流水线**。三条纪律继承自验证过的原型，必须严格遵守：

### 2.1 零确认直跑
解析完成后默认直接检索出报告，**不弹确认卡**。
- 唯一例外：仅当「单对象且措辞无法判定产品分析 / 竞品分析」时，弹一个 A/B chip 轻询问。
- 其余字段（对象数 / 维度 / 深度）一律用合理默认值。
- 报告顶部以一行「**本次假设**」明示本次运行口径，确认动作**后置到看报告后**（用户可增量重跑，如「加 Trae」「只盯定价」）。

### 2.2 证据可追溯
每条重要结论绑定：**结论、来源、时间、来源类型、可信度**。结论分三类：
- **事实**：可核实的客观信息。
- **洞察**：基于事实的分析判断。
- **建议**：面向决策的行动建议。
来源缺失时标注「未查证」，严禁编造。报告页保持干净，不堆免责声明。

### 2.3 约定写法 → 可视化渲染
报告用**固定约定写法**撰写（特定表格/标题结构），由渲染脚本生成图表页面。写作者只需遵守写法，不必关心图表实现；改视觉效果只动渲染器。

### 2.4 取舍哲学（为什么这么做）
- **不做数据库 / RAG / LangGraph / 量化评测**：MVP 聚焦单条可验证闭环，避免为"显得高级"引入复杂度（见 §6 边界）。
- **复用优于重写**：自包含 ECharts HTML 渲染器已成熟，网站化时只丢胶水代码，不复写视觉。
- **诚实优先**：原型就是原型，不把"待验证"写成"已实现"（见 §10 表达边界）。

## 3. 产品需求文档（PRD 摘要）

> 完整版见 `产品需求文档.md`（v0.1，评审中）。此处为决策相关要点。

### 3.1 背景与痛点
AI 行业迭代极快，相关信息高度分散于官网 / 博客 / 社区 / 新闻 / 代码仓库，人工搜集与交叉验证成本高、易滞后、易幻觉。痛点：信息分散耗时、来源不可信、缺乏统一分析框架、产出非结构化难沉淀。

### 3.2 5 类研究目标（入口）
1. **产品分析**：系统分析单个产品。
2. **竞品对比**：比较若干点名对象。
3. **市场扫描**：盘点一条赛道。
4. **产品选型**：按需求选工具。
5. **机会探索**：找空白与可切入方向。

支持自然语言输入（「分析一下可灵」）与结构化输入（直接填 1–3 个对象名）。

### 3.3 功能需求
- **意图解析与澄清**：产出对象 / 类型 / 限定维度 / 模式；信息不足时用选项式问题补全（每次只问一个、优先给选项）。
- **双模式**：
  - *对比模式*：用户点名 N 个 → 仅就这 N 个正面对比，不引入外部竞品。
  - *竞品分析模式*：用户仅给 1 个主体 → 先深析该主体，再对比默认 5 个竞品（候选初稿来自预置清单，确认后实时检索扩充）。
- **实时检索**：每次研究实时检索，来源含官网 / 帮助文档 / 定价页 / 博客 / 发布说明 / GitHub / Reddit / Product Hunt / Hacker News / 行业新闻。不做持久化知识库、不做 RAG（v1.1 起评估）。
- **证据系统**：见 §5。
- **分析引擎**：10 维度，见 §4。
- **可视化报告**：见 §7。
- **报告交付**：输出可视化网页 + 来源清单，支持归档与分享。

### 3.4 非功能需求
- 性能：标准深度下报告生成中位时长可控（随实测迭代）。
- 可靠性：来源缺失标「未查证」，绝不编造数据/份额/融资。
- 安全合规：仅用公开信息，不抓取需登录授权的内容。
- 可扩展：维度、预置清单、图表类型做成可配置，便于扩展到 AI 之外。

### 3.5 产品边界
- **MVP 范围**：单次研究闭环（输入 → 解析 →〔仅模式歧义时轻询问〕→ 检索 → 分析 → 可视化报告）。
- **明确不做（后置）**：持久化产品知识库、检索增强生成（RAG）、流程编排框架（LangGraph）、量化评测体系、持续追踪/订阅/历史积累、多智能体并行调研。

### 3.6 竞争与差异化
| 对比对象 | 差异点 |
|---|---|
| 通用搜索引擎 | 统一分析框架 + 证据纪律，而非零散链接 |
| 通用 AI 助手 | 决策导向、结构化、可视化、可复用，而非一次性问答 |
| 付费行业报告 | 实时、按需、低成本，而非高价静态报告 |

### 3.7 风险与缓解
- 实时检索质量依赖模型与搜索能力 → 多源并行 + 交叉验证 + 来源优先级。
- 信息时效性 → 报告标注数据时间，关键结论标来源时间。
- 幻觉风险 → 证据纪律（结论-来源绑定、事实/洞察/建议分类、未查证标注）。

## 4. 分析框架：10 维度定稿

排序固定（用户体验位于商业模式与增长之间；风险与短板永远置末）。维度无重叠，各为不同切面。

| # | 维度 | 看什么 |
|---|---|---|
| 1 | 市场与定位 | 目标用户、使用场景、品牌调性、赛道规模与位置 |
| 2 | 产品与核心功能 | 功能清单、核心场景覆盖、差异化功能点 |
| 3 | AI 能力 | 底层模型、基准表现、生成质量、上下文长度、一致性、生成速度 |
| 4 | 数据壁垒 | 数据资产（训练/反馈数据）、数据飞轮、护城河、隐私与合规 |
| 5 | 技术与生态 | 技术架构、API 开放、第三方集成、开源与开发者生态 |
| 6 | 商业模式与定价 | 免费/订阅/按量/企业版、价格带、变现边界 |
| 7 | 用户体验 | 易用性、界面、延迟、稳定性、客服（位于 6 与 8 之间） |
| 8 | 增长与运营 | 获客渠道、内容打法、社区、口碑、病毒机制 |
| 9 | 机会点 | 竞品未覆盖的空白、用户真实需求、可切入方向（按意图可选） |
| 10 | 风险与短板 | 合规风险、技术依赖、模式缺陷、竞争短板（置末） |

**评分口径**（以图表图例轻量呈现，不单独成段）：
- 1–5 分制，5 = 领先，3 = 行业平均，1 = 基本不覆盖。
- AI 能力按官方基准 + 实测；其余按公开资料 + 用户反馈综合判断（属分析洞察，非厂商披露）。

## 5. 证据系统（纪律细则）

1. **结论三类**：事实 / 洞察 / 建议（定义见 §2.2）。
2. **来源绑定**：每条重要结论后附来源角标，报告末以来源卡片汇总（官网 / 帮助文档 / 定价页 / 博客 / 发布说明 / GitHub / Reddit / Product Hunt / Hacker News / 新闻 / 财报）。
3. **未查证**：无法核实或来源缺失的结论内部标注「未查证」；报告页不展示未查证列表，仅以角标提示缺失。
4. **禁止编造**：严禁编造功能、价格、数据、份额、融资。来源存疑时降级为「未查证」而非臆测数值。
5. **评分口径**：1–5 分制在图表图例中轻量说明，不单独成段、不作免责声明。

## 6. 研究流程（5 步 + 双模式）

### 6.1 流程
1. **意图解析**：自然语言 / 结构化输入 → 对象（1–3）、目标类型（5 类）、限定维度、模式。
2. **研究简报（一次轻确认）**：对象 / 对比对象 / 意图 / 维度 / 深度 / 输出，用户确认（零确认直跑下此步实为「看报告后确认」）。
3. **实时检索**：按维度并行检索，每条结论带来源。
4. **撰写报告**：按 11 章节 + 约定写法写 Markdown，结论分事实/洞察/建议。
5. **渲染**：`scripts/build_report.py` 生成 ECharts 可视化 HTML。

### 6.2 双模式与示例
- **竞品对比模式**（输入「Kimi 和 豆包在长文本能力上谁强」）：仅比这 2 个，长文本维度高亮，不拉外部玩家。
- **竞品分析模式**（输入「系统分析一下可灵」）：先深析可灵，再对比预置 5 个（即梦/Runway/Pika/海螺视频/PixVerse），含机会点模块。

### 6.3 预置竞品清单逻辑
`references/preset-competitors.md` 为**静态种子表**（非 RAG、非向量库），仅作竞品分析模式快速建议。规则：按产品类别取同类其余产品（默认上限 5，不足跨相邻品类补）；主体不在表则不硬塞，改实时检索或轻问用户；厂商仅作括号标注，不作竞品建议（避免层级错配）。真实检索开放联网，远多于此表。

## 7. 可视化与渲染

### 7.1 报告章节（11 节）
执行摘要 / 市场概览 / 产品定位 / 功能矩阵 / AI 能力 / 商业模式 / 增长 / 竞争格局 / SWOT / 机会（按意图可选）/ 来源。

### 7.2 图表类型（约定写法 → ECharts）
| 图表 | 约定写法 | 说明 |
|---|---|---|
| 能力雷达图 | `1-5 分矩阵`表（首列维度、后列对象） | 多维能力叠加对比 |
| 市场地图 | `名称\|X\|Y\|规模` 表（置于含"地图"标题下） | 定位散点 |
| 机会地图 | 同上，置于含"机会"标题下 | 空白区气泡 |
| 时间线 | `## 时间线` 下 `- 日期：事件` 列表 | 版本/融资脉络 |
| 用户口碑 | `## 用户口碑` 下正负向引用或评分 | 口碑情感 |
| 优先级看板 | `Must:` / `Should:` / `Could:` 列表 | 建议分级 |

> 注：**维度热力矩阵已删除**（与雷达图重复），当前仅渲染雷达图。

### 7.3 视觉规范（2026-08-23 定稿）
- 配色：奶黄/橘黄系 —— 背景 `#FFF9F0`、主色 `#F59E0B`、浅黄 `#FCD34D`、边框 `#F3E6D0`、深色文本 `#2E2E38`。
- 报告头部日期 = 实际完整日期；产品名 = AIPM·瞭望台。
- 执行摘要：上下排列的全宽长条，关键词小标题橘色、正文深色区分。
- 图表类型：radar（能力雷达）、scatter（市场/机会地图）、timeline（时间线）、KPI 卡、功能点阵、机会 icon 卡。

### 7.4 渲染器
唯一可运行代码：`scripts/build_report.py`，把约定写法 Markdown 渲染为自包含 ECharts HTML（加载 ECharts CDN）。改渲染效果只动此脚本，再 `python3 scripts/build_report.py reports/xxx.md --output reports/output/xxx.html`。

## 10. 对外表达边界（简历 / 面试提示）

依据 AI 项目方法论，对外表达不得超出证据边界：
- **状态**：写「原型 / 离线验证」，**不写"上线系统"**（网站在搭、未部署）。
- **用户**：写「面向…设计 / 用公开样本验证」，**不写"服务了 N 位用户"**（无真实用户记录）。
- **指标**：不写提升百分比；量化评测体系未建，相关能力标「待验证」。
- **技术词**：每个词（Workflow / 检索 / 渲染器）都能答"解决哪个节点、为何不用更简单方法、怎么失败"——答不出就删。
- 每个结论可一路追回 PRD、评测、技术链路与原始材料，才写进对外表达。
