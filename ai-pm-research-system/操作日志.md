# AI PM Research System · 操作日志（真实落地版）

> 本文件夹是新项目根。仓库根目录的 `ai-intel-bureau/`（AI情报局）**原样保留，不删除、不改动**，作为本项目的可视化/工作流原型参考。

## 一、项目缘起
- 原 `ai-intel-bureau`（AI情报局）是轻量 WorkBuddy skill 原型，已验证：约定写法→可视化渲染、一次轻确认（Research Brief）、双模式意图解析、证据纪律（来源标注 + 事实/洞察/建议分类）。
- 现以《AI PM Research System》PRD（产品需求文档 + 产品搭建流程两份完整文档）为蓝图推倒重做，但**不照搬其技术栈**，按真实可落地情况裁剪。

## 二、关键决策（2026-08-23 确立）
1. **不建知识库 / 数据库**：MVP 不做 AI Product Database、不做持久化存储。每次研究**实时检索**即可。（PRD 原要求 MVP 建 20–50 个产品库，此处主动推翻。）
2. **不做 RAG（先）**：Evidence System 保留"结论绑定来源 / 事实-洞察-建议分类"的**纪律**，但向量检索（Embedding/Chunking/Vector DB）后置；当前靠实时检索 + 来源标注达成可靠性。
3. **评测体系后置**：RAG Evaluation（Recall@K）、Generation Evaluation（Faithfulness / Citation / Completeness / Insight Quality）、Product Evaluation 全部列为 v1.1+，MVP 不做。
4. **Workflow 不用 LangGraph**：MVP 用简单顺序 workflow（提示词式编排 / 轻量 Python 管道）。LangGraph 等复杂编排后置。理由：MVP 流程是固定的"Planner→检索→证据→分析→报告"，无需分支/状态持久/人类介入，引入框架只增复杂度。
5. **情报局保留**：`ai-intel-bureau/` 不动。
6. **新项目同仓库**：本文件夹 `ai-pm-research-system/` 即新项目根。
7. **MVP 范围 = 单次研究任务**：用户输入研究目标 → 生成 Research Brief → 检索 → 分析 → 可视化报告。持续追踪 / 订阅 / 历史积累后置。
8. **研究目标类型（沿用 PRD）**：产品分析 / 竞品对比 / 市场扫描 / 产品选型 / 机会探索（比原 AI情报局 仅"对比/竞品分析"双模式更完整）。
9. **维度体系（10 维纯中文定稿）** 见第三节。

## 三、维度体系（10 维纯中文定稿，2026-08-23 确认）
按用户要求：用户体验置于"商业模式"与"增长"之间；风险与短板置于最后；AI 能力独立单列；数据壁垒与技术生态**不合并**（拆为两项）。合并 PRD 维度与 AI情报局 维度、去重后共 10 项，全部用中文（不再保留英文来源标注）：

| # | 维度 | 看什么 |
|---|---|---|
| 1 | 市场与定位 | 目标用户、使用场景、品牌调性、赛道规模与位置 |
| 2 | 产品与核心功能 | 功能清单、核心场景覆盖、差异化功能点 |
| 3 | AI 能力 | 底层模型、基准表现、生成质量、上下文长度、一致性、生成速度 |
| 4 | 数据壁垒 | 数据资产（训练数据/用户反馈数据）、数据飞轮、护城河、隐私与合规 |
| 5 | 技术与生态 | 技术架构、API 开放、第三方集成、开源与开发者生态 |
| 6 | 商业模式与定价 | 免费/订阅/按量/企业版、价格带、变现边界 |
| 7 | 用户体验 | 易用性、界面设计、响应延迟、稳定性、客服（按用户要求置于 6 与 8 之间） |
| 8 | 增长与运营 | 获客渠道、内容打法、社区运营、口碑、病毒传播机制 |
| 9 | 机会点 | 竞品未覆盖的空白领域、用户真实需求、可切入方向 |
| 10 | 风险与短板 | 合规风险、技术依赖、商业模式缺陷、竞争短板（按用户要求置于最后） |

> 排序规则：维度 7（用户体验）严格位于"商业模式（6）"与"增长（8）"之间；维度 10（风险与短板）始终在末尾。维度 4 与 5 经用户最终决定拆开，不再合并。

## 四、真实落地版 PRD 解读（结合实际情况重述）
PRD 原蓝图是"AI Research OS"：五大模块（Product DB / Research Workflow / Evidence System / Analysis Engine / Visualization Layer）+ 技术栈（Next.js+FastAPI+Postgres+pgvector+LangGraph）+ 9 步搭建流程 + Evaluation 体系。

**按我们的真实情况裁剪后，MVP 只保留并落实这几条主干**：
- **入口**：研究目标驱动（非纯聊天），5 类研究目标；信息不足时用**选项式问题**补全（沿用 AI情报局 的轻确认思路，但允许按 PRD 多问几项）。
- **Brief**：生成 Research Brief（对象/范围/维度/输出），用户确认后进研究。
- **检索**：实时检索，来源含官网/文档/Pricing/Blog/Release Note/GitHub/Reddit/Product Hunt/新闻（不建库、不做 RAG）。
- **证据纪律**：每条重要结论绑定 来源/时间/类型/可信度；报告区分 Fact / Insight / Recommendation。
- **分析引擎**：按上述 10 维度输出 定位/用户/功能矩阵/AI能力/商业/增长/格局/SWOT/机会。
- **可视化**：Market Map / Feature Matrix / Capability Radar / Timeline / User Sentiment / Opportunity Map / Evidence Cards（复用 AI情报局 的"约定写法→HTML 渲染"作第一版，后续升级交互式）。
- **报告章节**：Executive Summary / Market Overview / Product Positioning / Feature Matrix / AI Capability / Business Model / Growth / Competitive Landscape / SWOT / Opportunity / Sources（对应 9 维度驱动）。
- **后置（明确不在 MVP）**：Product DB 持久化、RAG、LangGraph、Evaluation 体系、持续追踪/订阅、多 agent 并行。
