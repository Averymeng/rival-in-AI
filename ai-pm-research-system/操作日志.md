# AIPM·瞭望台 · 操作日志（真实落地版）

> 本文件夹是新项目根。仓库根目录的 `ai-intel-bureau/`（AI 情报局）**原样保留，不删除、不改动**，作为本项目的可视化 / 工作流原型参考。

## 一、项目缘起
- 原 `ai-intel-bureau`（AI 情报局）是轻量 WorkBuddy 技能原型，已验证：约定写法 → 可视化渲染、一次轻确认（研究简报）、双模式意图解析、证据纪律（来源标注 + 事实 / 洞察 / 建议分类）。
- 现以《AIPM·瞭望台》产品需求文档（含产品需求文档与产品搭建流程两份完整文档）为蓝图推倒重做，但**不照搬其技术栈**，按真实可落地情况裁剪。

## 二、关键决策（2026-08-23 确立）
1. **不建知识库 / 数据库**：最小可行产品阶段不做 AI 产品知识库、不做持久化存储。每次研究**实时检索**即可。（原产品需求文档要求最小可行产品阶段建立 20–50 个产品知识条目，此处主动推翻。）
2. **暂不做检索增强生成**：证据系统保留"结论绑定来源 / 事实-洞察-建议分类"的**纪律**，但向量检索（嵌入向量 / 文本分块 / 向量数据库）后置；当前靠实时检索 + 来源标注达成可靠性。
3. **评测体系后置**：检索评测（前 K 项召回率）、生成评测（忠实度 / 引用准确度 / 完整度 / 洞察质量）、产品评测全部列为 v1.1 之后，最小可行产品阶段不做。
4. **工作流不使用流程编排框架**：最小可行产品阶段用简单顺序工作流（提示词式编排 / 轻量 Python 管道）。流程编排框架（如 LangGraph）等复杂编排后置。理由：最小可行产品阶段流程是固定的"任务规划 → 检索 → 证据 → 分析 → 报告"，无需分支 / 状态持久 / 人工介入，引入框架只增复杂度。
5. **AI 情报局保留**：`ai-intel-bureau/` 不动。
6. **新项目同仓库**：本文件夹 `ai-pm-research-system/` 即新项目根。
7. **最小可行产品范围 = 单次研究任务**：用户输入研究目标 → 生成研究简报 → 检索 → 分析 → 可视化报告。持续追踪 / 订阅 / 历史积累后置。
8. **研究目标类型（沿用产品需求文档）**：产品分析 / 竞品对比 / 市场扫描 / 产品选型 / 机会探索（比原 AI 情报局仅"对比 / 竞品分析"双模式更完整）。
9. **维度体系（10 维纯中文定稿）** 见第三节。

## 三、维度体系（10 维纯中文定稿，2026-08-23 确认）
按用户要求：用户体验置于"商业模式"与"增长"之间；风险与短板置于最后；AI 能力独立单列；数据壁垒与技术生态**不合并**（拆为两项）。合并产品需求文档维度与 AI 情报局维度、去重后共 10 项，全部用中文（不再保留英文来源标注）：

| # | 维度 | 看什么 |
|---|---|---|
| 1 | 市场与定位 | 目标用户、使用场景、品牌调性、赛道规模与位置 |
| 2 | 产品与核心功能 | 功能清单、核心场景覆盖、差异化功能点 |
| 3 | AI 能力 | 底层模型、基准表现、生成质量、上下文长度、一致性、生成速度 |
| 4 | 数据壁垒 | 数据资产（训练数据 / 用户反馈数据）、数据飞轮、护城河、隐私与合规 |
| 5 | 技术与生态 | 技术架构、接口开放、第三方集成、开源与开发者生态 |
| 6 | 商业模式与定价 | 免费 / 订阅 / 按量 / 企业版、价格带、变现边界 |
| 7 | 用户体验 | 易用性、界面设计、响应延迟、稳定性、客服（按用户要求置于 6 与 8 之间） |
| 8 | 增长与运营 | 获客渠道、内容打法、社区运营、口碑、病毒传播机制 |
| 9 | 机会点 | 竞品未覆盖的空白领域、用户真实需求、可切入方向 |
| 10 | 风险与短板 | 合规风险、技术依赖、商业模式缺陷、竞争短板（按用户要求置于最后） |

> 排序规则：维度 7（用户体验）严格位于"商业模式（6）"与"增长（8）"之间；维度 10（风险与短板）始终在末尾。维度 4 与 5 经用户最终决定拆开，不再合并。

## 四、真实落地版产品需求文档解读（结合实际情况重述）
原产品需求文档蓝图是"AI 研究操作系统"：五大模块（产品知识库 / 研究流程 / 证据系统 / 分析引擎 / 可视化层）+ 技术栈（前端框架 Next.js、后端框架 FastAPI、关系型数据库 PostgreSQL、向量数据库 pgvector、流程编排框架 LangGraph）+ 九步搭建流程 + 评测体系。

**按我们的真实情况裁剪后，最小可行产品阶段只保留并落实这几条主干**：
- **入口**：研究目标驱动（非纯聊天），5 类研究目标；信息不足时用**选项式问题**补全（沿用 AI 情报局的轻确认思路，但允许按产品需求文档多问几项）。
- **研究简报**：生成研究简报（对象 / 范围 / 维度 / 输出），用户确认后进研究。
- **检索**：实时检索，来源含 官方网站 / 帮助文档 / 定价页 / 产品博客 / 版本发布说明 / GitHub / Reddit / Product Hunt / 行业新闻（不建库、不做检索增强生成）。
- **证据纪律**：每条重要结论绑定 来源 / 时间 / 类型 / 可信度；报告区分 事实 / 洞察 / 建议。
- **分析引擎**：按上述 10 维度输出 定位 / 用户 / 功能矩阵 / AI 能力 / 商业 / 增长 / 格局 / SWOT / 机会。
- **可视化**：市场地图 / 功能矩阵 / 能力雷达图 / 时间线 / 用户口碑 / 机会地图 / 证据卡片（复用 AI 情报局的"约定写法 → HTML 渲染"作第一版，后续升级交互式）。
- **报告章节**：执行摘要 / 市场概览 / 产品定位 / 功能矩阵 / AI 能力 / 商业模式 / 增长 / 竞争格局 / SWOT / 机会 / 来源（对应 10 维度驱动）。
- **后置（明确不在最小可行产品阶段）**：产品知识库持久化、检索增强生成、流程编排框架、评测体系、持续追踪 / 订阅、多智能体并行。
