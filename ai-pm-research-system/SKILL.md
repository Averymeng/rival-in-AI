# AIPM·瞭望台 · 技能与工作流

## 0. 定位与原则

- **定位**：面向 AI 产品决策者的智能研究与报告生成系统。输入一个研究目标，产出带证据来源的可视化研究报告。
- **范围**：仅 AI 相关领域（大模型 / AI 对话 / AI 绘画视频 / AI 办公效率 / AI 营销 / AI 编程 / AI 搜索 / AI 公司·基建 等）。
- **本质**：skill + workflow（固定顺序流水线），非 agent。MVP 不做自主决策、不做持久化数据库、不做检索增强生成（RAG）、不做流程编排框架、不做量化评测。
- **三个核心纪律**（继承自验证过的原型，必须严格遵守）：
  1. **零确认直跑**：解析完成后默认直接检索出报告，**不弹确认卡**。仅在「单对象且措辞无法判定产品分析 / 竞品分析」时，弹一个 A/B chip 轻询问；其余字段（对象数 / 维度 / 深度）一律用合理默认值。报告顶部以「本次假设」明示口径，确认动作后置到「看报告后」。
  2. **证据可追溯**：每条重要结论绑定来源；事实 / 洞察 / 建议 三类分开；无来源标注「未查证」，严禁编造。
  3. **约定写法 → 可视化渲染**：报告用固定约定写法撰写，由渲染脚本生成图表页面。

## 1. 研究任务入口（5 类目标）

支持自然语言输入（「分析一下可灵」）与结构化输入（直接填 1–3 个对象名）。识别研究目标类型：

1. **产品分析**：系统分析单个产品（如「帮我系统分析一下可灵」）。
2. **竞品对比**：比较若干对象（如「Kimi 和 豆包在长文本上谁强」）。
3. **市场扫描**：盘点一条赛道（如「AI 视频生成赛道有哪些主要玩家」）。
4. **产品选型**：按需求选工具（如「团队要选 AI 编程助手，怎么选」）。
5. **机会探索**：找空白与可切入方向（如「AI 客服赛道还有哪些未被满足的机会」）。

## 2. 意图解析（零确认直跑）

解析产出：
- 研究对象（1–3 个）
- 研究目标类型（上述 5 类之一）
- 限定维度（如「在 XX 方面」→ 该维度高亮，其余简略）
- 模式：**对比模式** / **竞品分析模式**

**双模式**：
- **对比模式**：用户点名 N 个对象 → 仅就这 N 个做正面对比，不引入外部竞品。
- **竞品分析模式**：用户仅给 1 个主体 → 先深析该主体，再对比固定数量（默认 5 个）竞品。候选初稿来自预置清单（见 `references/preset-competitors.md`），确认后实时检索扩充。

**默认直跑规则**：解析完成后**不弹任何卡**，直接按以下默认值进入检索：
- 对象数：竞品分析模式默认对比 5 个（候选来自预置清单）；用户点名 N 个则仅比 N 个。
- 维度：默认全 10 维；若用户语句显式限定（如「只在定价上比」），则该维度高亮、其余简略。
- 深度：默认「标准」（每对象 3–4 源）；用户未指定快 / 深，一律标准。

**唯一询问点（模式歧义）**：仅当「单对象且措辞无法判定产品分析还是竞品分析」（如仅说「分析一下可灵」），弹一个 chip：
`A 产品分析（只深析这个产品）　B 竞品分析（深析 + 对比竞品）`
其余情况一律不询问、直接跑：
- 点名多个对象 → 竞品对比；
- 明确说赛道 / 选型 / 机会 → 对应类型；
- 单对象且措辞已含对比意图（如「可灵和即梦比」）→ 竞品对比。

## 3. 报告假设声明（告知，非确认）

不再有阻塞式确认。检索前不卡用户，但报告**顶部**以一行「本次假设」明示本次运行口径，便于用户一眼判断是否需要重跑：

- 分析对象 / 对比对象
- 研究意图（5 类之一；机会探索 / 产品分析 / 选型 时展示「机会点」模块）
- 选用维度（默认全选，或用户显式限定的子集）
- 研究深度（快 / 标准 / 深）

用户若对假设不满，直接提出修改（如「加 Trae」「只盯定价」「改成深」），增量重跑即可——确认动作后置到「看报告后」。

## 4. 实时检索与数据获取

每次研究**实时检索**，来源包括（通用描述，不绑平台）：
- 官方网站、帮助文档、定价页、产品博客、版本发布说明
- GitHub（开源项目 / issues / releases，易获取）
- Reddit、Product Hunt、Hacker News（社区与新产品发现）
- 行业新闻、公开财报 / 融资报道

不做持久化知识库（v1.1 起评估）。不做检索增强生成（v1.1 起评估）。

## 5. 证据系统（纪律）

每条重要结论绑定：**结论、来源、时间、来源类型、可信度**。报告结论分三类：
- **事实**：可核实的客观信息。
- **洞察**：基于事实的分析判断。
- **建议**：面向决策的行动建议。

来源缺失时标注「未查证」，严禁编造数据 / 份额 / 融资。报告页**不展示「未查证」项列表与免责式评分口径说明**（保持页面干净）；评分口径以图表图例方式轻量呈现（见第 7 节）；来源以角标 / 来源卡片形式跟随结论。

## 6. 分析引擎（10 维度）

见 `references/dimensions.md` 定稿。排序固定：

1. 市场与定位
2. 产品与核心功能
3. AI 能力
4. 数据壁垒
5. 技术与生态
6. 商业模式与定价
7. 用户体验（位于 6 与 8 之间）
8. 增长与运营
9. 机会点（仅 机会探索 / 产品分析 / 选型 意图展示）
10. 风险与短板（永远置末）

## 7. 可视化报告

### 7.1 报告章节（11 节）

1. 执行摘要
2. 市场概览
3. 产品定位
4. 功能矩阵
5. AI 能力
6. 商业模式
7. 增长
8. 竞争格局
9. SWOT
10. 机会（按意图可选）
11. 来源

### 7.2 图表类型（7 类，ECharts 渲染）

| 图表 | 约定写法 | 说明 |
|---|---|---|
| 能力雷达图 | `1-5 分矩阵`表格（首列维度、后列对象） | 多维能力叠加对比 |
| 维度热力矩阵 | 同上表格 | 维度 × 对象 色块 |
| 市场地图 | `名称\|X\|Y\|规模` 表格（置于含"地图"标题下） | 定位散点 |
| 机会地图 | 同上，置于含"机会"标题下 | 空白区气泡 |
| 时间线 | `## 时间线` 下 `- 日期：事件` 列表 | 版本 / 融资脉络 |
| 用户口碑 | `## 用户口碑` 下正负向引用或评分 | 口碑情感 |
| 优先级看板 | `Must:` / `Should:` / `Could:` 列表 | 建议分级 |

### 7.3 渲染

报告 Markdown 经 `scripts/build_report.py` 渲染为自包含 HTML（加载 ECharts CDN，图表为 ECharts 实例，卡片为 HTML/CSS）。交互与精细 UI 后续迭代。

## 8. 产品边界

**MVP 范围**：单次研究任务闭环（输入 → 意图解析 → 〔仅模式歧义时轻询问〕→ 检索 → 分析 → 可视化报告）。零确认直跑，假设于报告顶部明示。
**明确不做（后置）**：持久化产品知识库、检索增强生成、流程编排框架（如 LangGraph）、量化评测体系、持续追踪 / 订阅 / 历史积累、多智能体并行调研。
